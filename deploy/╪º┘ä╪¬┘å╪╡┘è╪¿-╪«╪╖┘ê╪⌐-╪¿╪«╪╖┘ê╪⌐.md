# دليل تنصيب النظام على السيرفر — خطوة خطوة

> اقرا الدليل كله مرة قبل ما تبدأ، وبعدين نفّذ.
> كل مرحلة مبنية على اللي قبلها، فمتنطش خطوة.
> الوقت المتوقع: **من 3 لـ 4 ساعات** لأول مرة.

---

## المرحلة صفر — حضّر نفسك قبل ما تبدأ

### اللي محتاجه في إيدك

- [ ] الوركستيشن اللي هيبقى السيرفر (ويندوز 10 أو 11، الأفضل يكون Pro)
- [ ] كابل شبكة من السيرفر للسويتش — **مش واي فاي**
- [ ] باسورد الأدمن بتاع الويندوز على السيرفر
- [ ] دخول على الراوتر (عشان نحجز IP ثابت)
- [ ] فلاشة أو مجلد مشترك عشان تنقل ملفات النشر
- [ ] UPS (لو لسه مشتريتوش، كمّل التنصيب واشتريه قبل ما تفتح للعملاء)

### الملفات اللي هتنزّلها

نزّلهم كلهم الأول على السيرفر قبل ما تبدأ، عشان لو النت فصل متقفش:

| البرنامج | من فين |
|---|---|
| SQL Server 2022 **Express** | ابحث "SQL Server Express download" على موقع مايكروسوفت |
| SQL Server Management Studio (SSMS) | ابحث "SSMS download" |
| **ASP.NET Core 8 Hosting Bundle** | ابحث "dotnet 8 hosting bundle" |

> ⚠️ **دي أهم نقطة في الدليل كله:** لازم تنزّل **Hosting Bundle** بالذات.
> مش "Runtime" ولا "SDK" ولا ".NET Desktop Runtime".
> الـ Hosting Bundle هو الوحيد اللي بيربط الـ IIS بالتطبيق.
> لو نزّلت غيره، الموقع هيديك خطأ 500.19 ومش هتعرف السبب.

## المرحلة 1 — تجهيز الويندوز على السيرفر

### 1.1 غيّر اسم الجهاز

عشان تعرفه بسهولة على الشبكة.

1. اضغط زرار الويندوز واكتب `About` → افتح **About your PC**
2. دوس **Rename this PC**
3. اكتب: `POS-SERVER`
4. اعمل Restart

### 1.2 اقفل النوم والسبات

لو الجهاز نام، الكاشير هيقف. دي مش مبالغة — دي أكتر مشكلة بتحصل.

1. زرار الويندوز → اكتب `Power` → افتح **Power & sleep settings**
2. **Screen:** → `Never`
3. **Sleep:** → `Never`
4. دوس **Additional power settings** (على اليمين)
5. اختار خطة **High performance** (لو مش ظاهرة دوس Show additional plans)
6. جنب الخطة دوس **Change plan settings** → **Change advanced power settings**
7. افتح **Hard disk** → **Turn off hard disk after** → خليها `0` (يعني never)
8. افتح **Sleep** → **Hibernate after** → `Never`
9. دوس OK

وكمان من موجه أوامر Administrator:

```powershell
powercfg /hibernate off
```

### 1.3 ظبط التحديثات

مش عايزين ويندوز يعمل Restart وسط اليوم.

1. زرار الويندوز → `Windows Update` → **Advanced options**
2. **Active hours** → حدد من `8 صباحًا` لـ `2 بعد منتصف الليل`
   (يعني ساعات شغل المحل كلها)

### 1.4 IP ثابت — أهم خطوة في الشبكة

لو الـ IP اتغير، كل الأجهزة هتفقد السيرفر فجأة.

**الطريقة الأفضل (من الراوتر):**

1. اعرف الـ MAC بتاع السيرفر — من PowerShell:
   ```powershell
   Get-NetAdapter | Select Name, MacAddress, Status
   ```
   خد الكارت اللي حالته `Up`
2. ادخل على صفحة الراوتر (غالبًا `192.168.1.1`)
3. دور على **DHCP Reservation** أو **Static Lease** أو **Address Reservation**
4. اربط الـ MAC ده بالـ IP `192.168.1.10`
5. اعمل Restart للسيرفر

**الطريقة التانية (من الجهاز نفسه):**

1. زرار الويندوز → `ncpa.cpl` → Enter
2. كليك يمين على كارت الشبكة → **Properties**
3. اختار **Internet Protocol Version 4 (TCP/IPv4)** → **Properties**
4. اختار **Use the following IP address** واكتب:
   - IP address: `192.168.1.10`
   - Subnet mask: `255.255.255.0`
   - Default gateway: `192.168.1.1` (عنوان الراوتر عندك)
   - Preferred DNS: `192.168.1.1`
   - Alternate DNS: `8.8.8.8`
5. OK

> **ملاحظة:** لو شبكتك مش `192.168.1.x` غيّر الأرقام على حسب شبكتك.
> اعرف شبكتك بأمر `ipconfig` — شوف الـ IPv4 Address الحالي.

### 1.5 اتأكد إن الشبكة "خاصة"

مهم عشان جدار الحماية يسمح بالاتصال.

1. Settings → **Network & Internet** → دوس على الشبكة المتصلة
2. تحت **Network profile type** اختار **Private**

### 1.6 اعمل المجلدات

افتح PowerShell كـ **Administrator** (كليك يمين على زرار الويندوز → Terminal (Admin)):

```powershell
New-Item -ItemType Directory -Force -Path C:\POS\app
New-Item -ItemType Directory -Force -Path C:\POS\keys
New-Item -ItemType Directory -Force -Path C:\POS\backups
New-Item -ItemType Directory -Force -Path C:\POS\backups\keys
New-Item -ItemType Directory -Force -Path C:\POS\logs
New-Item -ItemType Directory -Force -Path C:\POS\deploy
```

## المرحلة 2 — تنصيب SQL Server

### 2.1 التنصيب

1. شغّل ملف `SQL2022-SSEI-Expr.exe` اللي نزّلته
2. هيسألك نوع التنصيب → اختار **Custom** (مش Basic)
   - ليه Custom؟ عشان محتاجين نفعّل Mixed Mode، وده مش موجود في Basic
3. حدد مكان التحميل → **Install** → استنى التحميل
4. هيفتح **SQL Server Installation Center**
5. اختار **New SQL Server stand-alone installation**
6. **License Terms** → علّم `I accept` → Next
7. **Microsoft Update** → سيبها فاضية → Next
8. **Install Rules** → لو فيه تحذير Firewall تجاهله → Next
9. **Feature Selection** → علّم على **Database Engine Services** بس → Next
10. **Instance Configuration:**
    - اختار **Default instance** لو تحب (اسمه هيبقى `localhost`)
    - أو **Named instance** واكتب `SQLEXPRESS` (اسمه هيبقى `localhost\SQLEXPRESS`)
    - **اكتب اللي اخترته على ورقة** — هتحتاجه في الـ connection string
11. **Server Configuration** → سيبها زي ما هي → Next
12. **Database Engine Configuration** — دي أهم شاشة:
    - **Authentication Mode** → اختار **Mixed Mode**
    - اكتب باسورد قوي لحساب `sa` واكتبه في مكان آمن
    - تحت **Specify SQL Server administrators** دوس **Add Current User**
    - Next
13. استنى لحد ما يخلص → **Close**

### 2.2 فعّل TCP/IP

من غير الخطوة دي، التطبيق مش هيعرف يوصل لقاعدة البيانات.

1. زرار الويندوز → اكتب `SQL Server 2022 Configuration Manager` → افتحه
   - لو مش لاقيه: افتح Run واكتب `SQLServerManager16.msc`
2. على الشمال: **SQL Server Network Configuration** → **Protocols for MSSQLSERVER**
   (أو `Protocols for SQLEXPRESS` لو عملت named instance)
3. كليك يمين على **TCP/IP** → **Enable** → OK على التحذير
4. على الشمال: **SQL Server Services**
5. كليك يمين على **SQL Server (MSSQLSERVER)** → **Restart**
6. برضه كليك يمين عليه → **Properties** → تبويب **Service**
   → **Start Mode** = `Automatic`
   (عشان يشتغل لوحده مع الجهاز)

### 2.3 نصّب SSMS

شغّل ملف SSMS اللي نزّلته → **Install** → استنى → **Restart** لو طلب.

## المرحلة 3 — اعمل قاعدة البيانات والمستخدم

1. افتح **SQL Server Management Studio**
2. في شاشة الاتصال:
   - Server name: `localhost` (أو `localhost\SQLEXPRESS`)
   - Authentication: **Windows Authentication**
   - **Connect**
3. دوس **New Query** (فوق على الشمال)
4. الصق الكود ده — **وغيّر الباسورد الأول**:

```sql
-- غيّر الباسورد ده لباسورد قوي واكتبه عندك
CREATE LOGIN posapp WITH PASSWORD = 'P@ssw0rd_Gheyar_Da_2026!';
GO

CREATE DATABASE RestaurantERP;
GO

USE RestaurantERP;
GO

CREATE USER posapp FOR LOGIN posapp;
ALTER ROLE db_owner ADD MEMBER posapp;
GO

PRINT 'تمام — القاعدة والمستخدم اتعملوا';
```

5. دوس **Execute** (أو F5)
6. لازم تشوف الرسالة `تمام` تحت في Messages

> **ليه مستخدم مخصص ومش `sa`؟**
> التطبيق هيشتغل تحت حساب IIS، والحساب ده ملوش صلاحيات على القاعدة.
> ولو استخدمت `sa` وحصل اختراق، الحساب ده بيتحكم في السيرفر كله مش
> قاعدتك بس.

## المرحلة 4 — نصّب IIS

### 4.1 فعّل IIS

1. زرار الويندوز → اكتب `Windows features` → افتح
   **Turn Windows features on or off**
2. علّم على **Internet Information Services**
3. افتحها (دوس على السهم) → **World Wide Web Services** → **Application
   Development Features** → علّم على:
   - **.NET Extensibility 4.8**
   - **ISAPI Extensions**
   - **ISAPI Filters**
4. برضه تحت **Web Management Tools** علّم على **IIS Management Console**
5. **OK** → استنى → **Restart** لو طلب

### 4.2 نصّب الـ Hosting Bundle

1. شغّل ملف `dotnet-hosting-8.x.x-win.exe`
2. علّم `I agree` → **Install** → **Close**
3. **مهم جدًا:** بعد ما يخلص، افتح PowerShell كـ Administrator واكتب:

```powershell
iisreset
```

> لو نسيت `iisreset`، الموقع هيدي خطأ حتى لو التنصيب صح.

### 4.3 اتأكد إن التنصيب ظبط

```powershell
dotnet --list-runtimes
```

لازم تشوف سطر فيه `Microsoft.AspNetCore.App 8.x.x`.
لو مش موجود، الـ Hosting Bundle متنصبش صح — أعد الخطوة 4.2.

## المرحلة 5 — انشر التطبيق من جهاز التطوير

**دي على جهازك اللي بتطوّر عليه، مش السيرفر.**

1. افتح PowerShell في مجلد المشروع
2. اكتب:

```powershell
dotnet publish -c Release -o C:\publish
```

3. استنى لحد ما يخلص وتشوف `Build succeeded`
4. افتح `C:\publish` — لازم تلاقي فيه:
   - `RestaurantERP.dll`
   - `web.config`
   - مجلد `wwwroot`
   - ملفات `appsettings*.json`
5. انسخ **محتويات** المجلد ده كلها على فلاشة

## المرحلة 6 — رفع الملفات على السيرفر

1. الصق كل اللي نسخته في `C:\POS\app`
2. اتأكد إن `RestaurantERP.dll` و `web.config` موجودين **مباشرة** في
   `C:\POS\app` — مش جوه مجلد تاني
   - لو لقيت `C:\POS\app\publish\RestaurantERP.dll` يبقى غلط — طلّع
     الملفات مستوى لبرّه

### 6.1 عدّل ملف الإعدادات

1. افتح `C:\POS\app\appsettings.Production.json` بالـ Notepad
2. عدّل السطور دي:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=RestaurantERP;User Id=posapp;Password=P@ssw0rd_Gheyar_Da_2026!;TrustServerCertificate=True;MultipleActiveResultSets=True;Connect Timeout=15;"
  },
  "Hosting": {
    "UseHttps": false,
    "AutoMigrate": false,
    "KeyRingPath": "C:\\POS\\keys"
  }
}
```

**انتبه لدول:**
- `Password=` → حط الباسورد الحقيقي بتاع `posapp` من المرحلة 3
- `Server=localhost` → لو عملت named instance خليها `Server=localhost\\SQLEXPRESS`
  (لاحظ الشرطتين `\\` مش واحدة)
- `KeyRingPath` → الشرطتين `\\` مهمين برضه

3. احفظ الملف

## المرحلة 7 — اعمل الموقع في IIS

### 7.1 إنشاء الموقع

1. زرار الويندوز → اكتب `IIS` → افتح **Internet Information Services (IIS) Manager**
2. على الشمال، افتح اسم الجهاز → كليك يمين على **Sites** → **Add Website**
3. املا كالتالي:
   - **Site name:** `POS`
   - **Physical path:** `C:\POS\app`
   - **Binding → Type:** `http`
   - **IP address:** `All Unassigned`
   - **Port:** `80`
   - **Host name:** سيبها **فاضية**
4. **OK**

> لو ظهرلك خطأ إن البورت 80 مستخدم، يبقى فيه موقع `Default Web Site`
> شغال. كليك يمين عليه → **Stop**. وبعدين أعد المحاولة.

### 7.2 ظبط الـ Application Pool

1. على الشمال دوس **Application Pools**
2. كليك يمين على `POS` → **Basic Settings**
   - **.NET CLR version** → اختار **No Managed Code**
   - OK
3. كليك يمين على `POS` تاني → **Advanced Settings**
   - **Start Mode** → `AlwaysRunning`
   - **Idle Time-out (minutes)** → `0`
   - **Regular Time Interval (minutes)** (تحت Recycling) → `0`
   - OK

> **ليه كده؟** الافتراضي إن IIS بيطفي التطبيق بعد 20 دقيقة سكون،
> وبيعيد تشغيله كل 29 ساعة. يعني أول كاشير الصبح هيستنى، وممكن التطبيق
> يعيد تشغيل نفسه وسط الشغل. الإعدادات دي بتمنع الاتنين.

### 7.3 التحميل المسبق

1. على الشمال دوس على **Sites**
2. دوس على `POS`
3. في النص، افتح **Configuration Editor**
4. من القائمة فوق اختار: `system.applicationHost/sites`
5. دوس على `...` جنب **(Collection)** → هيفتح جدول
6. لاقي السطر بتاع `POS` → دوس عليه → على اليمين افتح **applicationDefaults**
7. غيّر **preloadEnabled** لـ `True`
8. اقفل الشباك → دوس **Apply** على اليمين فوق

## المرحلة 8 — الصلاحيات

التطبيق محتاج يكتب في مجلدين. من غير الخطوة دي كل الكاشيرات هيخرجوا
من حساباتهم مع كل Restart.

من PowerShell كـ **Administrator**:

```powershell
icacls "C:\POS\keys" /grant "IIS AppPool\POS:(OI)(CI)M" /T
icacls "C:\POS\logs" /grant "IIS AppPool\POS:(OI)(CI)M" /T
icacls "C:\POS\app\wwwroot" /grant "IIS AppPool\POS:(OI)(CI)M" /T
```

لازم تشوف `Successfully processed` في كل سطر.

## المرحلة 9 — شغّل الـ Migrations

القاعدة لسه فاضية، محتاجين نعمل الجداول.

**من جهاز التطوير** (أسهل طريقة):

1. عدّل مؤقتًا `appsettings.json` على جهازك خليه يشاور على السيرفر:

```json
"DefaultConnection": "Server=192.168.1.10;Database=RestaurantERP;User Id=posapp;Password=...;TrustServerCertificate=True;"
```

2. في Package Manager Console:

```
Update-Database
```

3. **رجّع الـ connection string لحالته الأصلية بعد ما تخلص**

**أو من السيرفر مباشرة:**

```powershell
cd C:\POS\app
dotnet ef database update
```

(ده محتاج تنصيب `dotnet-ef` بأمر `dotnet tool install --global dotnet-ef`)

### اتأكد إن الجداول اتعملت

في SSMS: افتح `RestaurantERP` → **Tables** → لازم تلاقي جداول زي
`Orders` و `Products` و `AspNetUsers`.

## المرحلة 10 — جدار الحماية

من PowerShell كـ **Administrator**:

```powershell
New-NetFirewallRule -DisplayName "POS HTTP" -Direction Inbound `
  -Protocol TCP -LocalPort 80 -Action Allow -Profile Private
```

> **متعملش `-Profile Any`.** ده معناه إن الموقع مفتوح على أي شبكة
> يتوصل بيها الجهاز. `Private` بتخليه على شبكة المحل بس.

## المرحلة 11 — أول تشغيل واختبار

### 11.1 من السيرفر نفسه

1. افتح المتصفح على السيرفر
2. اكتب: `http://localhost/health`
3. **المفروض تشوف كلمة `Healthy`**

لو شفت `Healthy` → القاعدة شغالة والتطبيق شغال. تمام.
لو شفت خطأ → روح على قسم **المشاكل الشائعة** في آخر الدليل.

4. اكتب: `http://localhost`
5. المفروض تفتح صفحة تسجيل الدخول

### 11.2 سجّل دخول وغيّر الباسورد

1. سجّل دخول بالحساب الافتراضي:
   - Email: `admin@restaurant.com`
   - Password: (الباسورد الافتراضي من الـ seeder)
2. **غيّر الباسورد فورًا** من صفحة المستخدمين
3. اقفل أو امسح أي حسابات تجريبية تانية

### 11.3 من جهاز تاني على الشبكة

1. روح على أي جهاز تاني متوصل بنفس الشبكة
2. افتح المتصفح واكتب: `http://192.168.1.10`
3. لازم تفتح نفس الصفحة

**لو مفتحتش:** جرّب `ping 192.168.1.10` من الجهاز ده.
- الـ ping شغال بس الموقع لأ → مشكلة جدار حماية (ارجع للمرحلة 10)
- الـ ping مش شغال → مشكلة شبكة، اتأكد إن الاتنين على نفس الراوتر

## المرحلة 12 — اسم بدل الـ IP

عشان الكاشير ميكتبش أرقام.

### على كل جهاز (بما فيهم السيرفر):

1. افتح **Notepad كـ Administrator**
   (زرار الويندوز → اكتب Notepad → كليك يمين → **Run as administrator**)
2. File → Open → روح على:
   `C:\Windows\System32\drivers\etc\hosts`
   - غيّر الفلتر من `Text Documents` لـ **All Files** عشان تشوف الملف
3. أضف في آخر الملف سطر:

```
192.168.1.10   pos.club.local
```

4. احفظ

دلوقتي تقدر تفتح `http://pos.club.local` من أي جهاز.

> **الأفضل من كده:** لو الراوتر بتاعك بيدعم إضافة DNS records، ضيف
> السطر ده مرة واحدة في الراوتر بدل ما تلف على كل جهاز.
> الفايدة: لو غيّرت السيرفر بعد سنتين، هتغيّر سطر واحد بس.

## المرحلة 13 — أجهزة الكاشير والمطبخ

اعمل الخطوات دي على **كل شاشة** عندك.

### 13.1 اعمل اختصار

1. كليك يمين على سطح المكتب → **New** → **Shortcut**
2. في مكان الموقع الصق (حسب نوع الجهاز):

**شاشة الكاشير:**
```
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --kiosk http://pos.club.local/Cashier/Index --edge-kiosk-type=fullscreen --no-first-run --disable-features=TranslateUI
```

**شاشة المطبخ:**
```
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --kiosk http://pos.club.local/Kitchen/Index --edge-kiosk-type=fullscreen --no-first-run
```

**شاشة الطاولات:**
```
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --kiosk http://pos.club.local/Waiter/Tables --edge-kiosk-type=fullscreen --no-first-run
```

3. Next → سمّيه `POS` → **Finish**

> **للخروج من وضع Kiosk:** `Ctrl + Alt + Delete` أو `Alt + F4`

### 13.2 خلّيه يفتح لوحده مع الجهاز

1. اضغط `Win + R`
2. اكتب: `shell:startup` → Enter
3. انسخ الاختصار اللي عملته والصقه في المجلد ده

### 13.3 إعدادات الشاشة

على كل جهاز كاشير:
1. Settings → System → Power → **Screen: Never** و **Sleep: Never**
2. Settings → Windows Update → **Active hours** = ساعات الشغل
3. لو الجهاز فيه لمس: جرّب الكيبورد اللي بيطلع على الشاشة يشتغل
   (Settings → Time & Language → Typing → **Touch keyboard**)

### 13.4 تسجيل دخول تلقائي (اختياري)

عشان الجهاز يفتح على الكاشير على طول من غير باسورد ويندوز:

1. `Win + R` → اكتب `netplwiz` → Enter
2. شيل العلامة من **Users must enter a user name and password**

## المشاكل الشائعة

| المشكلة | السبب غالبًا | الحل |
|---|---|---|
| **خطأ 500.19** | الـ Hosting Bundle متنصبش | نصّبه واعمل `iisreset` |
| **خطأ 500.30** | مشكلة في الاتصال بالقاعدة | راجع الـ connection string والباسورد |
| **خطأ 502.5** | نسخة .NET غلط | `dotnet --list-runtimes` لازم تشوف `AspNetCore.App 8` |
| **الصفحة فاضية بيضا** | التطبيق وقع | Event Viewer → Windows Logs → Application |
| **بيفتح من السيرفر بس مش من الأجهزة** | جدار الحماية | المرحلة 10 |
| **كل الكاشيرات خرجوا فجأة** | مجلد `keys` مفيش صلاحية كتابة | المرحلة 8 |
| **بطء أول طلب الصبح** | Idle Time-out رجع 20 دقيقة | المرحلة 7.2 |
| **`Cannot open database`** | مستخدم `posapp` مش مربوط بالقاعدة | أعد سكربت المرحلة 3 |
| **الموقع بيحوّل لـ https ومش بيفتح** | `UseHttps` = true | خليها `false` في appsettings.Production.json |

### إزاي تقرا الأخطاء بالتفصيل

1. زرار الويندوز → اكتب `Event Viewer` → افتحه
2. على الشمال: **Windows Logs** → **Application**
3. على اليمين دوس **Filter Current Log**
4. في **Event sources** اختار `IIS AspNetCore Module V2`
5. دوس على أي خطأ أحمر واقرا الرسالة

الرسالة دي بتقول السبب الحقيقي — ابعتهالي لو مش فاهمها.

## إجراء التحديث (لما أبعتلك نسخة جديدة)

1. **اعمل backup الأول:**
   ```powershell
   powershell -File C:\POS\deploy\backup-server.ps1
   ```
2. استنى لحد ما المحل يقفل أو مفيش أوردرات مفتوحة
3. IIS Manager → كليك يمين على `POS` → **Manage Website** → **Stop**
4. انسخ الملفات الجديدة فوق `C:\POS\app`
   - ⚠️ **متمسحش** `appsettings.Production.json`
   - ⚠️ **متمسحش** مجلد `C:\POS\keys`
5. لو قلتلك فيه migration جديد، شغّله (المرحلة 9)
6. IIS → **Start**
7. افتح `http://pos.club.local/health` → لازم `Healthy`
8. اعمل أوردر تجريبي واطبعه **قبل ما تسيب المكان**
